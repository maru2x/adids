# シークレット管理

## 目的

この文書は、`adids` で扱う `.env` と周辺 secret を repo に混入させないための最小ルールを固定する。

## 現在の方針

- 実 secret は `.env` に置く
- `.env` は Git 追跡しない
- repo には `.env.example` だけを置く
- 初回作成は `make init-local-env` を使う
- 生成された `.env` は local 専用とし、公開センサ用 EC2 に安易にコピーしない
- `tests/manual/` に環境変数 dump や credential dump を保存しない

## 初回作成

```bash
make init-local-env
```

この target は `.env.example` をもとに `.env` を作り、次をランダム値で埋める。

- `ELASTIC_PASSWORD`
- `KIBANA_PASSWORD`
- `ENCRYPTION_KEY`

生成された `.env` は `chmod 600` で保存される。

## 自動チェック

```bash
make security-check
```

このチェックは次を拒否する。

- tracked な `.env`
- tracked な `.env.*` ただし `.env.example` を除く
- tracked な `tests/manual/environment_variables.json`
- tracked file 内の `ELASTIC_PASSWORD=...` / `KIBANA_PASSWORD=...` / `ENCRYPTION_KEY=...`
- `.env.example` 内の unsafe default secret 値

`make unit-test` からも自動で呼ばれる。

## 漏えい時の順番

1. secret を rotate する
2. 公開中のセンサや EC2 を止めるか隔離する
3. `.env` を repo 追跡から外す
4. 必要なら Git history を clean up する

重要なのは、history cleanup より先に rotate すること。

## Git history cleanup

remote に `.env` を push 済みだった場合、current branch から外すだけでは過去 commit には残る。
協調作業への影響が大きいので自動では実行しないが、必要なら次のように history を rewrite する。

```bash
git filter-repo \
  --path .env \
  --path tests/manual/environment_variables.json \
  --path tests/manual/dump_environment_variables.py \
  --invert-paths
```

その後、関係者と調整した上で force-push する。
ただし、history を消しても既に見られた secret は無効化されないので、rotate を先に終えておく。

## AWS センサに関する注意

`docker-compose.cowrie.yml` だけで Cowrie センサを動かす場合、local ELK 用 `.env` は必須ではない。
公開側 EC2 に ELK 用 `.env` を置かなくて済むなら、その方が安全である。
