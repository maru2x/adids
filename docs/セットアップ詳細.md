## 概要

このドキュメントでは、`adids` をローカルで動かすためのセットアップ手順を説明する。

ここで扱う範囲は次の通り。

- Python 3.11 の用意
- 仮想環境と依存パッケージのセットアップ
- Zeek モードを使う場合の前提確認
- 初回の動作確認
- `make run` の前に必要な設定変更

このセットアップを終えると、次のコマンドを実行できる状態になる。

- `make bootstrap`
- `make test`
- `make docs-check`
- `make pcap-to-log`
- `make log-to-csv`

詳細な設定項目や前処理の仕様は次を参照。

- `src/main/settings.json`: [設定ファイルの各種パラメータ.md](./設定ファイルの各種パラメータ.md)
- Zeek モードの前処理: [pcapファイルから特徴量を抽出する方法.md](./pcapファイルから特徴量を抽出する方法.md)
- CSV の前提: [CSVスキーマ仕様.md](./CSVスキーマ仕様.md)

## 前提条件

- Debian 12 を前提にしている
- Python 3.11 と `venv` が使えること
- Zeek モードを使う場合は `zeek` コマンドが必要
- `Simulation` を実行する前に、学習対象の CSV を `data/csv/` 配下に用意しておくこと

## 最短のセットアップ手順

すでに `python --version` が `3.11.x` になっているなら、まずは次でよい。

```bash
make bootstrap
make test
```

`make bootstrap` は次を自動で行う。

- `.venv` の作成
- `requirements.txt` による依存パッケージのインストール

補足:

- `make bootstrap` は `python3.11` を要求する
- `.python-version` と `pyenv` がある場合、`make bootstrap` はその Python を優先して使う
- `python3` が別バージョンでも、依存関係の都合で 3.11 以外では失敗する可能性が高い
- `python3.11` が無い環境では、先に 3.11 を導入してから実行する
- このリポジトリでは `.python-version` に `3.11.11` を置いている

## Python 3.11 を用意する方法

`zsh` を使っていて、OS パッケージで `python3.11` が入らない環境では `pyenv` の利用を勧める。

理由は 2 つある。

- `tensorflow==2.20.0` を含む依存関係の都合で、`Python 3.14` などでは `make bootstrap` が失敗することがある
- 環境によっては `apt install python3.11` が使えず、OS 標準パッケージだけでは `Python 3.11` を用意できない

そのため、`pyenv` は単なる好みではなく、このリポジトリが要求する `Python 3.11` を手元で確実に用意するための手段として使う。

### `pyenv` を使う場合

`zsh` と `pyenv` を使う前提で、最初は次の順で進めると詰まりにくい。

1. `pyenv` を導入する
2. `pyenv install 3.11.11`
3. リポジトリルートで `pyenv local 3.11.11`
4. `python --version` が `3.11.11` になっていることを確認する
5. `make bootstrap`
6. `make test`

```bash
sudo apt update
sudo apt install -y build-essential curl git libssl-dev zlib1g-dev \
  libbz2-dev libreadline-dev libsqlite3-dev libffi-dev liblzma-dev tk-dev
curl https://pyenv.run | bash
```

`~/.zshrc` に次を追加する。

```bash
export PYENV_ROOT="$HOME/.pyenv"
export PATH="$PYENV_ROOT/bin:$PATH"
eval "$(pyenv init -)"
```

新しい shell を開いてから:

```bash
pyenv install 3.11.11
cd ~/adids
pyenv local 3.11.11
python --version
make bootstrap
make test
```

### OS パッケージを使う場合

Debian / Ubuntu 系で OS パッケージから導入できる環境なら、次でもよい。

```bash
sudo apt update
sudo apt install python3.11 python3.11-venv
python3.11 --version
make bootstrap
make test
```

## Zeek の導入

Zeek モードを使う場合は、Python 依存とは別に `zeek` コマンドを導入する必要がある。

`requirements.txt` に Zeek が含まれていないのは、Zeek が `pip` で管理する Python パッケージではなく、OS 側に導入する外部コマンドだからである。

Debian / Ubuntu 系では、まず OS パッケージの有無を確認する。

```bash
apt search zeek
```

利用できる環境なら、次のように導入する。

```bash
sudo apt update
sudo apt install zeek
```

導入後は、`zeek` コマンドが見えていることを確認する。

```bash
zeek --version
```

環境によっては OS 標準パッケージに含まれないことがある。その場合は、Zeek 公式の案内に沿って環境ごとの導入方法を選ぶ。

## 初回確認

セットアップ直後は、まず次が通ることを確認する。

```bash
make test
make docs-check
```

目安:

- `make test`: `src/` の構文チェックと `tests/unit` が通る
- `make docs-check`: docs 関連の最低限の整合が通る

Zeek の実行環境まで確認したい場合は、必要に応じて `make test-e2e` を使う。
ただし、`zeek` コマンドが入っていない環境では skip する。

## よくある失敗

- `python --version` が 3.11 ではない
- 以前の Python で作った `.venv` を再利用している
- `zeek` を使うのに `zeek` コマンドが入っていない
- `src/util/FeatureExtract/Zeek/settings.json` の絶対パスをそのまま使っている
