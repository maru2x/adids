## 概要

`src/util/` 配下には、本プロジェクトに使用する補助スクリプトが保存されている。
補助スクリプトは、その用途ごとに以下のようにディレクトリを分けている。

- `FeatureExtract/`: PCAP や Zeek ログから特徴量 CSV を作る
- `DataModified/`: 既存 CSV を加工して別データセットを作る

各ディレクトリは、そのディレクトリ専用の `settings.json` を持つ運用を基本にする。

実験用の leaf CSV ディレクトリを作る全体手順は [実験用データセットの作りかた.md](./実験用データセットの作りかた.md) を参照。

## Zeek `conn.log` を runtime 互換 CSV にする `FeatureExtract/Zeek/feature_exporter.py`

`feature_exporter.py` は、Zeek `conn.log` から runtime 互換の leaf CSV を作るための sidecar exporter である。

対象は次の 2 つである。

- batch の `conn.log`
- growing live `conn.log`

対象外:

- `cowrie.json`
- Cowrie app log にしかない `eventid`, `message`, `session` など

`make` からは次で使う。

```bash
make feature-export FEATURE_EXPORT_ARGS='batch --input-dir data/logs/zeek/2201AusEast --output-dir data/csv/feature_export/2201AusEast --network-key 202201 --zeek-settings src/util/FeatureExtract/Zeek/settings.json'
```

live `conn.log` を増分 export したい場合は、次のように `live` mode を使う。

```bash
make feature-export FEATURE_EXPORT_ARGS='live --input-dir data/logs/zeek/live/cowrie/current --output-dir data/csv/feature_export/cowrie_live --label 1'
```

この utility は、`src/main/Simulation/` runtime の入力契約を変えずに `conn.log -> leaf CSV` の供給方法を増やすためのものである。
つまり exporter 単体では runtime をそのまま live 化するものではない。
一方で current repo の `make run-live` は、この `feature-export live` を内部で呼び出し、その出力 CSV の新着 row をそのまま推論に回す。

live demo を回し直す補助として、次の helper も追加した。

```bash
make demo-live-reset
make demo-live-inject-alert
```

- `make demo-live-reset`
  - `data/logs/zeek/live/local_iot/current/`, `data/csv/live/local_iot_demo/`, `data/live/state/` の生成物を掃除する
- `make demo-live-inject-alert`
  - emergency fallback として synthetic な `2223/tcp` 行を `conn.log` に追加する
  - concurrent write を避けるため、この target は `zeek-local-live` を停止してから書き込む

## CSV データセットを検査するスクリプト群 `Validate/`

runtime に渡す前の leaf CSV ディレクトリを点検したい場合は `Validate/` を使う。

### leaf CSV ディレクトリを検査する `validate_csv_dataset.py`

`validate_csv_dataset.py` は、指定した leaf CSV ディレクトリが runtime の想定契約を満たしているかを標準出力へ報告する。
加えて、契約チェックの各項目が `OK` / `警告` / `NG` のどれだったかを日本語で列挙し、データサマリも合わせて出す。

実行例:

```bash
python3 src/util/Validate/validate_csv_dataset.py
```

既定では `src/util/Validate/settings.json` の `CsvDatasetValidator` を読む。
一時的に path や schema を変えたい場合だけ、CLI 引数で上書きできる。

```bash
python3 src/util/Validate/validate_csv_dataset.py data/csv/zeek/conn/2201AusEast --schema zeek
```

Zeek 由来 CSV の通信方向サマリを、現在の `NetworkAddress` 定義に合わせて出したい場合は、必要に応じて `--zeek-settings` で参照元の `settings.json` を上書きできる。

`make` からは次でよい。

```bash
make validate-csv-dataset
```

主に確認すること:

- 指定 path が leaf CSV ディレクトリであること
- 直下に `.csv` 以外のファイルやサブディレクトリが混ざっていないこと
- 各 CSV に必要列があること
- `daytime` が `%Y-%m-%d %H:%M:%S` 形式であること
- `label` が数値として読めること
- `local_orig`, `local_resp` が Zeek スキーマで読める真偽値であること
- 各 CSV 内で `daytime` が非減少であること
- ディレクトリ全体でも、ファイル名順に読んだとき `daytime` が後戻りしないこと

主なサマリ:

- 総フロー数、CSV 数、先頭 / 末尾 `daytime`、観測期間
- `label=0` / `label=1` の割合と件数
- `外向き` / `内向き` / `その他/不明` の割合と件数
- `LABEL_FEATURES` の値分布
  - 既定の Zeek 設定では `conn_state` ごとの割合と件数
- CSV 全列の欠損割合と件数

通信方向の判定は、原則として `src/util/FeatureExtract/Zeek/settings.json` の `NetworkAddress` を使う。
挙動は Legacy の `snd` / `rcv` 判定に合わせており、概ね次の意味になる。

- `外向き`
  - `src` が `MALICIOUS`
  - または `src` が `BENIGN` で `dst` が `BENIGN` ではない
- `内向き`
  - `dst` が `MALICIOUS`
  - または `dst` が `BENIGN` で `src` が `BENIGN` ではない
- `その他/不明`
  - それ以外

`settings.json` の `SCHEMA` を `legacy` にするか、`--schema legacy` を指定すると Legacy スキーマの必須列で検査する。

## 抽出済みのCSVファイルを加工するスクリプト群 `DataModified/`

`DataModified/` は、抽出済み CSV に対して何らかの加工を行いたい場合に使用するスクリプトを集めている。

実行時は `src/util/DataModified/settings.json` を編集してから、対象スクリプトを直接実行する。
例：

```bash
python3 src/util/DataModified/two_csv_combine.py
```

よくある「片側の時刻をもう片側へ合わせてから 1 つに混ぜる」作業には、次のラッパーも使える。

```bash
make align-mix
```

### 時刻を合わせてから結合する `align_mix.py`

`align_mix.py` は、2つの CSV ディレクトリのうち片側をもう片側の先頭 `daytime` に合わせて平行移動し、そのまま時系列結合まで行う。

設定項目:

- `INPUT_DIR_A`
  - 1つ目の入力ディレクトリ
- `INPUT_DIR_B`
  - 2つ目の入力ディレクトリ
- `ALIGN_TO`
  - どちらの時系列に合わせるか
  - `A` なら `INPUT_DIR_A` 側の最小 `daytime` を基準にして `INPUT_DIR_B` をずらす
  - `B` なら逆に `INPUT_DIR_A` を `INPUT_DIR_B` 側へずらす
- `SHIFTED_OUTPUT_DIR`
  - 平行移動した側の中間出力先
  - 空ディレクトリまたは未作成ディレクトリにする
- `OUTPUT_DIR`
  - 最終的な結合結果の出力先
  - `make run` に渡すなら、ここも CSV ファイルだけが並ぶ leaf ディレクトリにする
- `CHUNK_SIZE`
  - 1つの出力 CSV に入れる最大行数

前提:

- 入力 CSV には `daytime` 列があること
- すべての path は別々にしておくこと
- `SHIFTED_OUTPUT_DIR` と `OUTPUT_DIR` は空ディレクトリまたは未作成ディレクトリにしておくこと

挙動:

`ALIGN_TO` で指定した側の最小 `daytime` を基準時刻として使い、反対側の CSV 群を平行移動したうえで、既存の `two_csv_combine.py` と同じ規約で時系列結合する。
入力 2 系統の CSV は編集せず、中間結果は `SHIFTED_OUTPUT_DIR`、最終結果は `OUTPUT_DIR` に出力される。

### 2つのCSVファイルを結合する `two_csv_combine.py`

`two_csv_combine.py` は、2つの CSV ディレクトリを `daytime` 列の時系列順で結合し、結果を一定件数ごとに分割して出力する。

設定項目:

- `INPUT_DIR_A`
  - 1つ目の入力ディレクトリ
  - 典型的には良性側の leaf CSV ディレクトリを入れる
  - 例: `data/csv/zeek/conn/2201AusEast`
- `INPUT_DIR_B`
  - 2つ目の入力ディレクトリ
  - 典型的には悪性側の leaf CSV ディレクトリを入れる
  - 例: `data/csv/zeek/conn/2201Lab04`
- `OUTPUT_DIR`
  - 結合結果の出力先ディレクトリ
  - `make run` に渡すなら、ここも CSV ファイルだけが並ぶ leaf ディレクトリにする
- `CHUNK_SIZE`
  - 1つの出力 CSV に入れる最大行数
  - 既定値は `3000`

前提:

- 入力 CSV には `daytime` 列があること
- 入力ディレクトリには結合対象の CSV 群が入っていること

結合後は、必要に応じて `src/main/Simulation/settings.json` の `DATASETS_DIR_PATH` に `OUTPUT_DIR` を設定して `make run` へ渡す。

挙動：

`INPUT_DIR_A` で指定された CSV ファイル群と `INPUT_DIR_B` で指定された CSV ファイル群が、`daytime` の値に基づいて昇順に結合される。
`CHUNK_SIZE` で指定した行数ごとに異なる CSV ファイルとして書き出され、 `OUTPUT_DIR` に出力される。
`INPUT_DIR_A` もしくは `INPUT_DIR_B` に対する編集が行われない。
`OUTPUT_DIR` は空ディレクトリにしておく必要があり、入力 2 系統の CSV ヘッダは一致している必要がある。
各入力ディレクトリには、少なくともどこかの CSV に1行以上のデータが必要である。

### CSVファイルの時間を上書きする `csv_daytime_override.py`

`src/util/DataModified/csv_daytime_override.py` は、1つのCSVディレクトリのdaytimeを、設定した日時に基づいて一斉にずらす。

設定項目：

- `INPUT_DIR`
  - 入力ディレクトリ
- `OUTPUT_DIR`
  - 出力ディレクトリ
- `BASELINE`
  - 基準となる日時

前提:

- 入力 CSV には `daytime` 列があること
- 入力ディレクトリには結合対象の CSV 群が入っていること

挙動：

`INPUT_DIR`で指定された CSV ファイル群の一番最初の時刻が `BASELINE` で指定された日時になり、そのほかの時刻も平行にずらされる。
ずらされた結果の CSV ファイルは `OUTPUT_DIR` に出力され、`INPUT_DIR` に存在する CSV ファイルには編集が行われない
出力ファイル名は、ずらした後の各 CSV の先頭 `daytime` が分かるように付け直される。


## 可視化スクリプト群 `Visualize/`

`Visualize/` は、抽出済み CSV や runtime 結果をグラフ化して確認したいときに使う。

現在の推奨導線は `src/util/Visualize/graph/` 配下で、入力として

```text
data/csv/zeek/conn/2201AusEast
```

のような **CSV ファイルだけが並ぶ leaf ディレクトリ** を受ける。

### データセット全体の特徴量を概観する `feature_dataset_overview.py`

Zeek `conn` leaf CSV ディレクトリ全体を集計し、以下を出力する。

- 総行数、ファイル数、時刻範囲
- feature ごとの欠損率、平均、標準偏差などの summary CSV
- `daytime` の時間バケットごとの flow 数グラフ
- `label` 分布グラフ
- 数値 feature のヒストグラム

実行例:

```bash
python3 src/util/Visualize/graph/feature_dataset_overview.py data/csv/zeek/conn/2201AusEast
```

必要なら出力先や対象 feature を指定できる。

```bash
python3 src/util/Visualize/graph/feature_dataset_overview.py \
  data/csv/zeek/conn/2201AusEast \
  --output-dir exp/2201AusEast_overview \
  --features duration orig_bytes resp_bytes orig_pkts resp_pkts
```

### スライディングウィンドウで分布差を測る `sliding_window_feature_drift.py`

データセット全体、または指定した参照範囲を基準分布として、スライディングウィンドウごとの feature 分布差を測定する。

出力:

- feature ごとの Wasserstein 距離
- feature ごとの KS statistic
- 平均 drift の時系列 CSV / PNG
- feature ごとの drift グラフ

実行例:

```bash
python3 src/util/Visualize/graph/sliding_window_feature_drift.py \
  data/csv/zeek/conn/2201AusEast \
  --window-hours 4 \
  --step-hours 1
```

参照分布を特定期間に限定したい場合:

```bash
python3 src/util/Visualize/graph/sliding_window_feature_drift.py \
  data/csv/zeek/conn/2201AusEast \
  --reference-start "2022-01-10 00:00:00" \
  --reference-end "2022-01-11 00:00:00" \
  --window-hours 4 \
  --step-hours 1
```

### 旧スクリプトについて

従来の観測用 script は `src/util/Visualize/legacy/` へ退避してある。
過去の研究作業を再現したいときは参照できるが、固定 path や旧スキーマ前提が混ざるので、新規利用ではまず `graph/` 側を使う方が安全である。
