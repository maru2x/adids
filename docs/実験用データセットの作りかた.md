# 実験用データセットの作りかた

## 概要

`make run` を実行するには、`DATASETS_DIR_PATH` にそのまま渡せる leaf CSV ディレクトリを用意する必要がある。

典型例:

```text
data/csv/zeek/conn/2201AusEast
```

このディレクトリには CSV ファイルだけが並んでいる必要がある。
途中ディレクトリを指定しても runtime は再帰探索しない。

重要:
- 良性データセットと攻撃データセットの収集時刻がずれている場合、そのままでは `make run` の時系列実験に使いづらい
- 必要に応じて、先に `csv_daytime_override.py` でどちらか一方の `daytime` をそろえる
- その後で `two_csv_combine.py` を使って 1 つの実験用 CSV ディレクトリにまとめる
- 上の 2 手順をまとめて行いたいときは `make align-mix` を使える

細かい設定項目は [ユーティリティ利用方法.md](./ユーティリティ利用方法.md) も参照。

## 1. Zeek で CSV を作る

まずは PCAP から Zeek ログを作り、その後 CSV 化する。

```bash
make pcap-to-log
make log-to-csv
```

この 2 手順をまとめて実行したい場合は、次でもよい。

```bash
make pcap-to-csv
```

前提:
- `src/util/FeatureExtract/Zeek/settings.json` を先に編集しておく
- `LogToCsv.TARGET_LOGS` は通常 `["conn.log"]` を使う

補足:
- `make log-to-csv` は変換進捗を標準出力へ出す
- `conn.log` を出力した場合は、その leaf CSV dir に対して自動で runtime 契約チェックとデータサマリを出す
- `make pcap-to-log` / `make pcap-to-csv` で既存の log batch dir が見つかった場合、対話端末なら利用方法を確認する
- 非対話環境で既存 dir の扱いを決めたい場合は、`make pcap-to-csv PCAP_TO_CSV_ARGS="--replace"` のように明示指定する

出力例:

```text
data/csv/zeek/
  conn/
    2201AusEast/
      20220101000000.csv
      20220101003000.csv
```

この `data/csv/zeek/conn/2201AusEast` が runtime に渡せる leaf ディレクトリになる。

## 2. 時刻をそろえる

収集日や開始時刻が違う CSV 同士を混ぜたいときは、先に `daytime` を平行移動させる。
この手順を単体で行うなら `csv_daytime_override.py` を使う。

使うスクリプト:

```bash
python3 src/util/DataModified/csv_daytime_override.py
```

設定:
- `src/util/DataModified/settings.json` の `DaytimeOverride.INPUT_DIR`
- `src/util/DataModified/settings.json` の `DaytimeOverride.OUTPUT_DIR`
- `src/util/DataModified/settings.json` の `DaytimeOverride.BASELINE`

用途:
- 攻撃側だけ別日に収集していて、良性側の時系列へ重ねたい
- runtime の `SESSION_START_DATE` に合わせて先頭時刻を整理したい

## 3. 2 系統の CSV を結合する

良性側と攻撃側を 1 つの実験用データセットへまとめるときは `two_csv_combine.py` を使う。

```bash
python3 src/util/DataModified/two_csv_combine.py
```

設定:
- `INPUT_DIR_A`
- `INPUT_DIR_B`
- `OUTPUT_DIR`
- `CHUNK_SIZE`

入力はどちらも leaf CSV ディレクトリにする。

例:

```text
INPUT_DIR_A = data/csv/zeek/conn/2201AusEast
INPUT_DIR_B = data/csv/zeek/conn/2201Lab04_shifted
OUTPUT_DIR  = data/csv/zeek/conn/2201AusEast_mixed
```

出力された `OUTPUT_DIR` は、`daytime` 昇順で並んだ CSV だけを含む leaf ディレクトリになる。

## 3.5 よく使う 2 手順をまとめて実行する

攻撃側を正常側へ重ねてから 1 つの実験用データセットを作るような運用では、`make align-mix` を使うと手数が少ない。

```bash
make align-mix
```

設定:
- `INPUT_DIR_A`
- `INPUT_DIR_B`
- `ALIGN_TO`
- `SHIFTED_OUTPUT_DIR`
- `OUTPUT_DIR`
- `CHUNK_SIZE`

典型例:

```text
INPUT_DIR_A         = data/csv/zeek/conn/2201AusEast
INPUT_DIR_B         = data/csv/zeek/conn/2201Lab04
ALIGN_TO            = A
SHIFTED_OUTPUT_DIR  = data/csv/modif/2201Lab04_shifted/conn
OUTPUT_DIR          = data/csv/modif/2201AusEast_mixed/conn
```

`ALIGN_TO = A` なら `INPUT_DIR_A` の先頭時刻へ `INPUT_DIR_B` を寄せ、そのまま `OUTPUT_DIR` へ mixed dataset を作る。
逆に `ALIGN_TO = B` にすれば、`INPUT_DIR_A` 側を `INPUT_DIR_B` に寄せる。

## 4. runtime に渡す

最後に `src/main/Simulation/settings.json` を編集する。

```json
"FeatureSchema": {
  "MODE": "zeek"
},
"DATASETS_DIR_PATH": "/home/.../data/csv/zeek/conn/2201AusEast_mixed"
```

そのうえで実行する。

```bash
make run
```

## 5. よくある詰まりどころ

- `DATASETS_DIR_PATH` に `data/csv/zeek/conn` のような途中ディレクトリを指定してしまう
- 時刻をそろえずに良性 CSV と攻撃 CSV を結合してしまう
- `conn` 以外のログ種別ディレクトリを runtime に渡してしまう
- `FeatureSchema.MODE` を `legacy` のままにしてしまう
