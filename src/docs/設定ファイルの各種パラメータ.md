# 設定ファイルの各種パラメータ

## 概要

`adids` には役割の違う `settings.json` が3つある。

- `src/main/settings.json`: `make run` で使う本体設定
- `src/util/FeatureExtract/Zeek/settings.json`: Zeek モードの前処理設定
- `src/util/FeatureExtract/Legacy/settings.json`: Legacy モードの前処理設定

初めて触る場合は、まず次の2つを編集することが多い。

1. `src/util/FeatureExtract/Zeek/settings.json`
2. `src/main/settings.json`

特に重要なのは、Zeek モードで生成した CSV を本体に渡すとき、`src/main/settings.json` の `DATASETS_DIR_PATH` を `data/csv/.../conn` のような **CSV ファイルだけが並ぶ末端ディレクトリ** に合わせること。

## 1. `src/main/settings.json`

### 役割

`make run` の挙動を決める本体設定。以下を制御する。

- どの特徴量スキーマを使うか
- どの CSV を読むか
- どのモデルを使うか
- 再学習をするか
- 何秒ごとに評価するか
- 動的再学習時のドリフト検知窓をどうするか

### `OS`

TensorFlow 実行時の環境変数。

- `TF_CPP_MIN_LOG_LEVEL`
  - TensorFlow のログ量を制御する
  - `3` にすると INFO / WARNING を抑えたい意図になる
- `TF_FORCE_GPU_ALLOW_GROWTH`
  - GPU メモリの確保方法に関する設定
- `CUDA_VISIBLE_DEVICES`
  - 使う GPU を制御する
  - `-1` なら GPU を使わない意図

注意:
- 現状の実装では、これらは `SettingsLoader` 読み込み後にセットされる
- TensorFlow import 自体はそれより前に走るので、完全には効いていない

### `USER_DIR`

実験結果の出力先を決める基準パス。

- `exp/<timestamp>_<dataset>_<mode>_<model>/` の出力先を作るときに使う
- 実験環境へ持っていくときは、その環境の絶対パスに合わせる必要がある

### `MODEL_CODE`

使うモデルの種類。

- `0`: DNN
- `1`: RNN
- `2`: Autoencoder
- `3`: SVM 風の単層モデル
- `4`: Logistic Regression
- `5`: LSTM
- `6`: Random Forest
- `7`: Gradient Boosting

現状の目安:
- `0`, `4`: 比較的使いやすい
- `1`: 形状の取り扱いに注意
- `2`: 現在の学習経路とは整合していない
- `5`: 現在の入力形状とは整合していない
- `6`, `7`: `tensorflow_decision_forests` が必要だが、現状の `requirements.txt` には入っていない

### `FOUNDATION_MODEL_PATH`

初期重みをロードしたいときの pickle ファイルへのパス。

- 空文字ならランダム初期化
- `USER_DIR` からの相対パスではなく、`ModelFactory` 側で `USER_DIR` と結合して使う

### `FeatureSchema`

CSV のどの列をどう扱うかを決める。

#### `MODE`

- `split`
  - Zeek モードで作った `conn.csv` などを前提にしたスキーマ
  - `VECTOR_FEATURES` と `LABEL_FEATURES` を使う
- `legacy`
  - 旧 `PcapToCsvExtractor.py` の出力スキーマ
  - `LEGACY_FEATURES` を使う

#### `LABEL_COLUMN`

正解ラベル列の名前。

- 通常は `label`

#### `LEGACY_FEATURES`

`MODE=legacy` のときに入力特徴量として使う列名の配列。

#### `LABEL_FEATURES`

`MODE=split` のとき、モデルを分けるキーに使う列。

- 現在の既定値は `conn_state`
- 例えば `conn_state=SF` と `conn_state=S0` で別モデルを持つ構成になる

#### `VECTOR_FEATURES`

`MODE=split` のとき、数値入力としてモデルに渡す列。

- 既定値は `duration`, `orig_bytes`, `resp_bytes`, `orig_pkts`, `resp_pkts`, `orig_ip_bytes`, `resp_ip_bytes`, `missed_bytes`, `local_orig`, `local_resp`
- `local_orig`, `local_resp` は `true/false`, `1/0` などを数値へ変換する
- 空文字は一部列で `0.0` として扱う

注意:
- `VECTOR_FEATURES` と `LABEL_FEATURES` は重複してはいけない
- 指定した列が CSV にないと実行時にエラーになる

### `DATASETS_DIR_PATH`

本体が読む CSV のディレクトリ。

ここが一番重要。

現状の実装では:
- 指定したディレクトリ直下のエントリを `open()` する
- サブディレクトリは自動では潜らない
- つまり **CSV ファイルだけが並んでいるディレクトリ** を指定する必要がある

Zeek モードの典型例:

```text
src/util/FeatureExtract/Zeek/settings.json で
  LogToCsv.OUTPUT_ROOT_DIR_PATH = data/csv/unproc
  LogToCsv.TARGET_LOGS = ["conn.log"]
  LogToCsv.INPUT_DIR_PATH = data/logs/unproc/test_region

make log-to-csv
```

このあと本体に渡すべき `DATASETS_DIR_PATH` は、次のような末端ディレクトリになる。

```text
data/csv/unproc/test_region/conn
```

`data/csv` や `data/csv/unproc` のような途中ディレクトリをそのまま指定すると、ディレクトリを読もうとして失敗する。

### `SESSION_START_DATE`

Simulation を何時から開始した扱いにするか。

- 各 CSV の `daytime` と比較して、これより前のデータはスキップされる
- 最初のデータがこれより後ろなら、その時刻に合わせて内部基準時刻がずれる

### `TargetRange`

Simulation をどれくらいの長さ走らせるか。

- `DAYS`, `HOURS`, `MINUTES`, `SECONDS` の合計で終了時刻を決める
- ここを短くするとスモークテスト向け、長くすると本実験向けになる

### `ONLINE_MODE`

`src/main/settings.json` 側では現在参照されていない。

- いまの `make run` は実質的に Simulation 用
- Live モードは README にもあるとおり未実装

### `RETRAINING_MODE`

再学習の方式。

- `nt`: No Retrain
  - 推論と評価のみ
  - 再学習しない
- `st`: Static Retrain
  - `RETRAINING_INTERVAL` ごとに蓄積データで再学習する
- `dy`: Dynamic Retrain
  - ドリフト検知窓で異常を見つけたときだけ再学習する

使い分けの目安:
- スモークテスト: `nt`
- 一定間隔の再学習実験: `st`
- ドリフト検知込みの実験: `dy`

### `RETRAINING_INTERVAL`

静的再学習の周期。単位は秒。

- `st` では再学習周期として使われる
- `nt` では意味がない
- `dy` では現在の実装上ほぼ使われていない

### `EVALUATE_UNIT_INTERVAL`

評価結果をまとめる周期。単位は秒。

- この間隔ごとに `res_eval.csv` に1行追加される
- 短い CSV でスモークテストをすると、ここが長すぎて `res_eval.csv` が空のまま終わることがある

### `TrainingDefine`

学習時の基本ハイパーパラメータ。

- `EPOCHS`
  - 学習エポック数
- `BATCH_SIZE`
  - 学習バッチサイズ

### `DriftDetection`

`RETRAINING_MODE=dy` のときだけ意味がある。

#### `OBS_MODE`

現状のコードでは参照されていない。

#### `DRIFT_DETECTION_UNIT_INTERVAL`

動的再学習で、ドリフト検知を何秒ごとにチェックするか。

#### `ENSEMBLE_METHOD_CODE`

複数窓を持ったときの予測統合方法。

- `0`: 先頭の窓だけ使う
- `1`: 多数決

注意:
- 現状の実装では、各窓の予測値は sigmoid の生確率
- `0` はその値を `int()` にしてしまうので、`0.7` でも `0` になる
- そのため、現状の `dy` では `1` を使う方が安全

#### `WindowConfig`

ドリフト検知窓の配列。各要素は次を持つ。

- `CURRENT_WIN_SIZE`
  - 現在窓の長さ。単位は秒
- `PAST_WIN_SIZE`
  - 過去窓の長さ。単位は秒
- `METHOD_CODE`
  - `0`: コサイン類似度
  - `1`: ユークリッド距離
- `K`
  - 近傍数
- `THRESHOLD`
  - ドリフト判定の閾値

## 2. `src/util/FeatureExtract/Zeek/settings.json`

### 役割

Zeek モードの前処理設定。

- `make pcap-to-log`
- `make log-to-csv`

の2つがこのファイルを読む。

パスは:
- 絶対パス
- プロジェクトルートからの相対パス

のどちらでも書ける。

### `PcapToLog`

#### `INPUT_DIR_PATH`

`.pcap` ファイルを含むディレクトリ。

- 再帰的に `.pcap` を収集する
- 単一ファイルは受けない

#### `OUTPUT_ROOT_DIR_PATH`

Zeek ログの出力ルート。

実際の出力は次の形になる。

```text
<OUTPUT_ROOT_DIR_PATH>/<input_dir_name>/<timestamp>/...
```

例:

```text
data/logs/unproc/test_region/20250513234727/conn.log
```

補足:
- `timestamp` は Zeek ログ中の最初の `ts` を JST の `YYYYMMDDHHMMSS` にしたもの
- すでに `<input_dir_name>` が存在する場合は警告を出して続行する
- 同じタイムスタンプが重なった場合は `_01`, `_02` を付ける

### `LogToCsv`

#### `INPUT_DIR_PATH`

CSV 化したいログ入力。

- ログバッチディレクトリ
  - 例: `data/logs/unproc/test_region`
- 単一ログディレクトリ
  - 例: `data/logs/unproc/test_region/20250513234727`

のどちらでも受ける。

#### `OUTPUT_ROOT_DIR_PATH`

CSV の出力ルート。

実際の出力は次の形になる。

```text
<OUTPUT_ROOT_DIR_PATH>/<batch_name>/<target_log_name>/<timestamp>.csv
```

例:

```text
data/csv/unproc/test_region/conn/20250513234727.csv
```

#### `TARGET_LOGS`

CSV 化したいログ名の配列。

例:

```json
["conn.log"]
```

または

```json
["conn.log", "http.log"]
```

挙動:
- 単一指定でもログ名ごとのサブディレクトリを作る
- 複数指定した場合も、各ログは別ディレクトリへ出力する
- 異なるログ種別を1つの CSV に混ぜない

本体 (`make run`) に渡す前提なら、まずは `conn.log` だけにしておくのが無難。

#### `NETWORK_KEY`

同じファイル内の `NetworkAddress` から参照するキー。

- ラベル付けに使う
- `BENIGN`, `MALICIOUS`, `EXCEPTION` をどのセットで見るかを決める

### `NetworkAddress`

ネットワークごとのアドレス定義。

各キーは次を持つ。

- `BENIGN`
  - 正常側ネットワーク
- `MALICIOUS`
  - 攻撃側ネットワーク
- `EXCEPTION`
  - CSV に入れたくないアドレス

ラベル付けのルール:
- `src` または `dst` が `MALICIOUS` に入れば `label=1`
- `src` が `BENIGN` で `dst` が `BENIGN` でなければ `label=0`
- `dst` が `BENIGN` で `src` が `BENIGN` でなければ `label=0`
- それ以外は CSV に出さない
- `EXCEPTION` に入る通信は CSV に出さない

注意:
- 現状の Zeek モードでは `EXCEPTION` は `log-to-csv` の段階で効く
- Zeek 実行前には除外していないので、処理量削減効果は Legacy より弱い

## 3. `src/util/FeatureExtract/Legacy/settings.json`

### 役割

Legacy モードの `pcap -> csv` 直変換用設定。

### `ONLINE_MODE`

- `1`: オンライン sniff を想定
- `0`: オフラインの pcap 処理

### `TRAFFIC_DATA_PATH`

入力の pcap パス。

- ディレクトリを前提に使うのが自然
- 現状の Legacy 導線はメンテナンス優先度が低いので、Zeek モードの方を推奨

### `FLOW_TIMEOUT`

フローを切るまでのタイムアウト秒数。

- Legacy 特徴量の interval 系・length 系にも影響する

### `CAPTURE_TIMEOUT`

オンライン sniff 時のタイムアウト秒数。

### `MAX_WORKER`

オフライン処理時の並列ワーカー数。

### `NetworkAddress`

Zeek 側と同じく `BENIGN`, `MALICIOUS`, `EXCEPTION` を持つ。

Legacy では:
- `EXCEPTION` を sniff フィルタ段階で除外する
- `BENIGN` / `MALICIOUS` で `label` を決める

## 4. 最初に触るときのおすすめ設定

### Zeek モードで `conn.csv` を作って Simulation を回す

1. `src/util/FeatureExtract/Zeek/settings.json`

```json
{
  "PcapToLog": {
    "INPUT_DIR_PATH": "data/pcap/test_region",
    "OUTPUT_ROOT_DIR_PATH": "data/logs/unproc"
  },
  "LogToCsv": {
    "INPUT_DIR_PATH": "data/logs/unproc/test_region",
    "OUTPUT_ROOT_DIR_PATH": "data/csv/unproc",
    "TARGET_LOGS": ["conn.log"],
    "NETWORK_KEY": "202201"
  }
}
```

2. 前処理を実行

```bash
make pcap-to-log
make log-to-csv
```

3. `src/main/settings.json`

- `FeatureSchema.MODE = "split"`
- `DATASETS_DIR_PATH = "/absolute/path/to/data/csv/unproc/test_region/conn"`
- スモークテストなら `RETRAINING_MODE = "nt"`
- 動的再学習を試すなら `RETRAINING_MODE = "dy"` と `ENSEMBLE_METHOD_CODE = 1`

4. 本体を実行

```bash
make run
```

## 5. よくあるミス

- `DATASETS_DIR_PATH` に `data/csv` や `data/csv/unproc` を入れてしまう
  - 途中ディレクトリなので失敗する
- `TARGET_LOGS` に複数ログを入れたのに、本体でその親ディレクトリを指定してしまう
  - `conn`, `http` などに分かれて出るので、どれを使うか明示する必要がある
- `MODEL_CODE=6` や `7` を選んだのに追加依存が入っていない
- 短い CSV で `EVALUATE_UNIT_INTERVAL` が長すぎて `res_eval.csv` が空になる
