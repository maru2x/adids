# 開発タスク

## 目的

このドキュメントは、今の `adids` がどこまで整理されていて、何が未整理かを開発者向けにまとめたもの。

- これから人が直すとき
- Codex の別モデルに続きを頼むとき
- 実験環境へ持っていく前に残タスクを確認したいとき

の引き継ぎ用メモとして使う。

## 現在の安定導線

今の前処理で一番安定している流れはこれ。

1. `src/util/FeatureExtract/Zeek/settings.json` を編集
2. `make pcap-to-log`
3. `make log-to-csv`
4. `src/main/settings.json` の `DATASETS_DIR_PATH` を `data/csv/.../conn` のような末端ディレクトリへ合わせる
5. `make run`

補足:
- `make run` にそのまま `data/csv` や `data/csv/unproc` を渡す構成にはなっていない
- 本体は現状「CSV ファイルだけが並んだディレクトリ」を前提にしている

## 直近で完了したこと

- Zeek 前処理を `src/util/FeatureExtract/Zeek/` へ整理
- `pcap-to-log` を settings.json 駆動に統一
- `log-to-csv` を settings.json 駆動に統一
- `TARGET_LOGS` を配列化
- `TARGET_LOGS` ごとに出力ディレクトリを分離
- 単一指定でも `conn/` のようなログ名ディレクトリを切る仕様に統一
- `EXCEPTION` を `log-to-csv` で除外する処理を追加
- `src/docs/設定ファイルの各種パラメータ.md` を利用者向けに整備
- `tests/` と GitHub Actions の CI を追加

## 優先度つきタスク

### P0: 本体の既定設定で `make run` が落ちる問題を直す

状況:
- `src/main/settings.json` の既定値は `DATASETS_DIR_PATH = /home/mnl/adids/data/csv`
- しかし本体は `DATASETS_DIR_PATH` 直下の全エントリを `open()` するだけ
- `data/csv/unproc` のようなディレクトリがあると `IsADirectoryError` で落ちる

選択肢:
1. 本体を修正して再帰的に CSV を探索できるようにする
2. 既定値を `data/csv/test_run.csv` 系の専用ディレクトリへ変える
3. `DATASETS_DIR_PATH` が不正なとき、早い段階で説明付きエラーを出す

推奨:
- まずは `SessionDefiner.run()` 側でディレクトリを弾き、説明付きエラーにする
- そのあと余裕があれば再帰探索対応を検討する

対象ファイル:
- `src/main/SessionDefiner.py`
- `src/main/settings.json`
- `README.md`

### P0: `RETRAINING_MODE=dy` + `ENSEMBLE_METHOD_CODE=0` の予測集約を直す

状況:
- 動的モードでは各窓の予測値として sigmoid の生確率を保持している
- それを `int()` しているため `0.7 -> 0` になる
- 既定設定のままだと予測がほぼ全部 `0` に潰れる

最低限の修正案:
- `0` を使うなら `>= 0.5` で二値化して返す
- もしくは `0` を廃止し、`1` を既定にする

対象ファイル:
- `src/main/DriftDetection.py`
- `src/main/settings.json`

### P1: TensorFlow 環境変数の反映タイミングを直す

状況:
- `SettingsLoader` で環境変数を入れているが、TensorFlow import はそれより前に走る
- CPU-only 環境でも CUDA 初期化ログが出る

修正案:
- `Run.py` の先頭で settings を先読みする
- もしくは `SettingsLoader` を import 前に使えるよう整理する

対象ファイル:
- `src/main/Run.py`
- `src/main/SettingsLoader.py`
- `src/main/SessionDefiner.py`
- `src/main/ModelFactory.py`

### P1: `EXCEPTION` を Zeek 実行前にも効かせる

状況:
- Legacy では sniff フィルタで早期除外していた
- Zeek モードでは CSV 化後に落としているだけなので、処理量削減になっていない

案:
- Zeek に渡すフィルタを構築する
- もしくは `pcap-to-log` 前に pcap を事前フィルタする

対象ファイル:
- `src/util/FeatureExtract/Zeek/PcapToLogExtractor.py`
- `src/util/FeatureExtract/Zeek/settings.json`

### P1: `MODEL_CODE` ごとの実運用可否を整理する

現状の所見:
- `0`: DNN は使える
- `1`: RNN は動くが形状の扱いに注意
- `2`: Autoencoder は今の教師あり学習経路と整合していない
- `4`: Logistic Regression は使える
- `5`: LSTM は今の入力形状だと失敗する
- `6`, `7`: 追加依存がないので失敗する

必要な作業:
- README / docs にサポート状況を書く
- 使えないモデルは選べないようにするか、明示エラーを改善する

対象ファイル:
- `src/main/ModelFactory.py`
- `src/docs/設定ファイルの各種パラメータ.md`

## 引き継ぎ時の注意

- `src/docs/pcapファイルから特徴量を抽出する方法.md` は既存の文章をベースにしている。大きく書き換えるより追記で揃える方が安全
